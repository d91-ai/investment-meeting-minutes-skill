# 投资会议纪要整理 Skill

这个仓库保存 Codex 使用的中文投资会议纪要整理 Skill。它把投资研究场景中的录音、转写稿、DOCX/TXT/Markdown 文稿或音频+文稿材料，整理为一份来源忠实的 Markdown 纪要。

## 输出

正式 Markdown 包含：

- `会议纪要`：从已经完成的参考原文派生，保留结论、关键依据、条件、风险、数字、动作和不确定性，同时压缩讨论过程与重复论证。
- `参考原文`：优先建立，直接对照未编辑来源，主动修复上下文唯一的 ASR 错词、标准术语、语病和断句；专名或数字口径不能唯一恢复时显式列疑。不得直接复制输入。所有来源轮次必须被处理，长材料包对整轮删除记录理由。
- `存疑与待确认`：仅在名称、代码、术语、残缺片段或来源内数字冲突无法唯一解决时出现。
- `重要信息修改记录`：在实体、代码、数字、单位、产品或术语发生可见实质纠正，补充标的代码，或参考原文发生语境化非轻量改写时出现，复用处理时已有的依据，不启动第二轮查询。

两份正文都保留真实发言顺序、问答边界、人称、判断、条件、数字、时间、动作和不确定性。最终 Markdown 只由主流程生成和修改。

纠错门槛按事实载荷而不是词类决定。语法成立、能够表达完整事实的来源词不会仅因另一说法更常见、更专业或更符合行业而被替换；身份、类别、动作、属性、范围和强度发生变化时，必须有独立的本场正向证据。

## 运行方式

1. 先根据用户指令和材料确定会议类型；无法可靠判断时先向用户确认，不默认归类或先生成正文。随后读取文稿；有音频时使用本地 SenseVoiceSmall＋fsmn-vad 完成一次转录与时间轴准备，不再对整场音频运行第二套 ASR。
2. 音频和文稿同时存在时，由主流程比较覆盖、顺序、逐字性、噪声、遗漏和人工修正后选择正文源。
3. 根据上下文耦合和延迟选择路线：强连续上下文且容量允许时直接生成；存在清晰独立板块或完整 Q&A 边界时可用少量并行段。不使用固定字数路由。
4. 分段只发生在自然段、发言轮次或完整 Q&A 之间。脚本只做线性容量分包，不生成全文预标注副本，也不求全局最优。
5. 无发言人标签时，基模在生成正文的同一次处理中判断保守的匿名轮次。
6. 每段先完成参考原文，再派生更短的会议纪要；主流程只处理接缝、格式、统一实体写法和具体冲突，不再进行第二轮全文语义复核。
7. 汇总本场实际投资标的并一次批量匹配证券代码，同时只核验会改变成稿文字的少量实体候选；本地批量查询后如仍需联网，所有未解决实体只合并召回一轮，不逐项追查。单一历史或外部结果不能证明模糊原音；代码无法唯一匹配时明确列疑，不猜测。
8. 同次来源对照和语义检查完成后直接交付 Markdown。生产路径不运行 validator 或另外的结构检查，不回读整份成稿；归档和导出仅在用户明确要求时执行。

语病修正、无用信息、重复、短回复归属、问答边界、实体唯一性、标的归因和原意漂移都由模型结合上下文判断。脚本不使用关键词或硬规则替代这些语义判断。

## 主要文件

- `skills/投资会议纪要整理/SKILL.md`：核心工作流与边界。
- `references/output_contract.md`：共同 Markdown 格式。
- `references/meeting_types/`：多人复盘会、公司交流、专家交流格式。
- `references/verification_policy.md`：名称、代码、术语核验边界。
- `references/long_material_workflow.md`：仅长材料加载的轻量分包流程。
- `scripts/transcribe_audio.py`：本地 ASR。
- `scripts/build_speaker_turn_manifest.py`：显式 turn 解析与线性容量分包。
- `scripts/assemble_speaker_turn_edits.py`：长材料返回的顺序和覆盖检查；完整过程 JSON 写入 `--out`，标准输出仅返回紧凑摘要。
- `scripts/query_symbol_candidates.py`：查询本地证券名称和代码候选。
- `scripts/build_entity_search_plan.py`：为重要非人专名生成包含原词、少量音形候选和完整读音的单个组合查询；只扩充候选，不确认身份。
- `evals/tools/validate_meeting_minutes_contract.py`：开发者按需使用的客观 Markdown 结构校验，不属于生产 Skill。
- `evals/fixtures/meeting_minutes/`：合成 Markdown 开发样例，不随生产 Skill 加载。

## 开发时按需验证具体纪要

```bash
python3 evals/tools/validate_utf8_text.py NOTE.md --require-cjk
python3 evals/tools/validate_meeting_minutes_contract.py NOTE.md --json
```

首次使用音频或机器环境改变后，只检查本地模型缓存：

```bash
python3 skills/投资会议纪要整理/scripts/transcribe_audio.py --check-model-cache
```

## 隐私边界

不要提交真实会议材料、录音、正式纪要、私有转写、临时链接、token、会话数据、模型权重或本机配置。外部核验只处理非人专名，只发送候选名称、代码、术语和必要公开别名；人名仅使用当前会议或用户证据。不发送会议原文或未公开业务上下文。公共 fixtures 必须是合成或充分脱敏内容。
