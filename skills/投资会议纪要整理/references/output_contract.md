# 共享输出契约

本文件是最终 Markdown 结构、多人复盘会小段标题、正文粗体、公司交流与专家交流问题格式的唯一正式契约。各会议类型 Reference 只解释本类型的语义，不得另行定义冲突格式。

## 一、最终 Markdown 骨架

```markdown
# 投资会议纪要

会议日期：2026-08-04
会议标题：测试多人复盘会
会议类型：多人复盘会
会议系列：研究所周会
整理时间：2026-08-04
整理依据：会议转写稿

---

## 一、发言整理

### 张三

#### 【中芯国际(688981.SH)｜北方华创(002371.SZ)| 半导体设备】

正文。

#### 【商业航天】

正文。

---

## 二、存疑与待确认

| 原始表述 | 当前判断 | 候选项 | 人工确认 |
|---|---|---|---|
| **OCF** | 暂无法确认 | OCS | |
```

上述骨架中的 `会议日期`、`会议标题`、`会议类型`、`会议系列` 和 `整理时间` 是共享必填元信息；`整理依据` 可按实际来源填写。公司交流还必须增加普通字体的 `会议标的：公司名(代码)`；该字段只写已核验的单一公司及证券代码，不得混入板块、行业或“待确认”占位。标题、元信息标签和存疑表标题一律不加粗。

## 二、发言整理正文边界

`## 一、发言整理` 只能包含源材料中的发言内容及必要的正常编辑，包括纠正明显错字、清理无意义断句、补全可核验的公司名称与证券代码，以及在不改变含义的前提下理顺句子。

以下内容不得进入发言整理正文：

- AI 的判断、解释、总结、推论和补充背景；
- 核验过程、处理说明、候选项说明和置信度；
- 整理者插入的独立提示段落；
- 为满足格式而虚构的标的、主题、事实或观点。

AI 核验过程只能进入内部 `doubtful_items`、verification sidecar、MAS 过程 artifact，以及最终存疑表的“当前判断”“候选项”等审核列。

正文必须保留原始发言顺序和第一人称。多人复盘会不得按板块或标的重新汇总；同一发言人后来再次发言时，继续按实际顺序出现。

## 三、多人复盘会小段标题

### 3.1 唯一结构

有明确证券标的时，只使用一种四级小段标题：

```markdown
#### 【长鑫科技(688825.SH)| 存储】
```

多个标的共享同一主题时：

```markdown
#### 【兆易创新(603986.SH)｜江波龙(301308.SZ)| 存储】
```

格式要求：

- 多个标的之间使用全角 `｜`；
- 标的部分与板块部分之间使用半角 `|`；
- 半角 `|` 前无空格，后恰好一个空格；
- 每个证券标的均使用“公司名称(证券代码)”；
- 小段标题全部使用普通字体；
- 不得输出五级标题；
- 标的与主题必须合并在同一个四级小段标题中。

该段没有明确证券标的时，不得虚构标的，只写同一种四级主题标题：

```markdown
#### 【存储】
```

标题的语义归属按 `meeting_types/review_meeting.md` 判断。

## 四、粗体与存疑

### 4.1 正文粗体

只有源材料中仍无法确认的最小原文片段使用粗体，并保留在原句原位置：

```markdown
我听到客户可能采用 **OCF** 方案，但具体名称还需要确认。
```

已确认的公司名纠正、证券代码补充、转录修复和句子整理均使用普通字体。不得因为内容由 AI 修改或补全就加粗，也不得把整句、整段或标题机械加粗。

不得在正文另行复制存疑片段，不得插入整理者说明、候选项或存疑时间戳。音频时间戳只进入内部审核材料或最终存疑表。

### 4.2 最终存疑表

每个正文粗体片段必须对应 `## 二、存疑与待确认` 中的一行；每个表格存疑项也必须对应正文中的一个最小粗体片段。

纯文稿输入使用：

```markdown
| 原始表述 | 当前判断 | 候选项 | 人工确认 |
|---|---|---|---|
| **OCF** | 暂无法确认 | OCS | |
```

音频输入且时间戳可靠时使用：

```markdown
| 时间戳 | 原始表述 | 当前判断 | 候选项 | 人工确认 |
|---|---|---|---|---|
| 00:12:34 | **OCF** | 暂无法确认 | OCS | |
```

如果没有存疑项，省略整个 `## 二、存疑与待确认` 章节，不输出空表或占位行。

## 五、公司交流与专家交流问题格式

问题统一使用普通字体的中文方括号行：

```markdown
【今年是否会扩产？】

回答正文。
```

问题后直接跟回答，不增加问答角色标签。问题不得加粗，也不得使用字母或中文前缀标记提问与回答。

具体语义分别见 `meeting_types/listed_company.md` 和 `meeting_types/expert_call.md`。

## 六、会议类型路由

- 多人复盘会：使用本文件的四级小段标题，并读取 `meeting_types/review_meeting.md`。
- 公司交流：使用本文件的问题格式，并读取 `meeting_types/listed_company.md`。
- 专家交流：使用本文件的问题格式，并读取 `meeting_types/expert_call.md`。

任何会议类型 Reference、脚本、模板或样例都不得覆盖本文件定义的共享格式。
