# 共享输出契约

本文件定义最终 Markdown 的共享结构、双层纪要边界、标题、粗体和内嵌存疑规则。各会议类型 Reference 只定义本类型的语义，不得覆盖本文件。

## 一、最终 Markdown 骨架

```markdown
# 会议纪要

- 会议类型：专家交流
- 输入来源：录音+文本
- 会议日期：2026-08-04

> 标记说明：正文内容中的加粗表示段落标题，或未完全确认、无法安全修改、原始表述缺少明确口径而需要人工复核的内容。

### 提问者1

**【询问今年是否会扩产】**

### 专家

**【需求改善但扩产仍取决于客户订单】**

专家表示，扩产仍取决于客户订单。

# 原文校对

### 提问者1

**【询问今年是否会扩产】**

今年是否会扩产？

### 专家

**【需求改善但扩产仍取决于客户订单】**

我觉得需求是改善了，但扩产还要看客户订单。
```

所有会议均必须包含 `# 会议纪要` 和 `# 原文校对` 两层。文末不得输出“存疑与待确认”章节、表格、空表或“重要信息修改记录”。

元信息固定使用无粗体项目符号：`会议类型`、`输入来源`、`会议日期`。公司交流另加 `会议标的：公司名(代码)`；仅在已核验且对识别单一公司必要时填写。文件名承载会议标题、日期和类型，正文不再强制填写会议标题、会议系列或整理时间。

## 二、两层正文边界

### 2.1 会议纪要

“会议纪要”是便于阅读的归纳层：

- 可以压缩相邻问答、合并同一逻辑、使用第三人称和“专家称”“管理层表示”等纪要语言；
- 必须保留结论的证据边界、否定、自我纠正、条件、时间、数字、因果、比较对象和不确定性；
- 不得把专家或管理层判断升级为事实，不得补写外部背景、AI 推论或投资结论；
- 每个重要结论必须能在“原文校对”层找到对应依据。

### 2.2 原文校对

“原文校对”是接近原始问答的人工复核层，不是逐字转写：

- 保留真实发言顺序、发言人、问答关系和第一人称；
- 允许修正明显错字、错误断句、无信息寒暄、机械重复和可唯一确认的实体或术语；
- 不得删去或改写否定、自我纠正、观点强度、条件、时间、数字、交易动作和实质信息；
- 不得按主题重排，也不得为了简洁把多轮问答合并为无来源边界的段落。

AI 判断、候选项、核验过程、处理说明和补充背景不得进入任一正文层。

## 三、标题与发言人

专家交流和公司交流使用“三级发言人标题 + 加粗方括号概括标题”：

```markdown
### 提问者2

**【询问货源稳定性、当前规模与扩产能力】**

### 专家

**【既有渠道支持稳定供货，月度来料为百万GB级】**
```

概括标题必须由紧邻发言直接支持：提问可写“询问……”，回答可写核心结论，但不得夸大观点强度或补写结论。标题本身允许加粗，且不属于存疑标记。

多人复盘会保留三级发言人和四级小段标题。纪要层可以使用加粗概括标题；原文校对层继续使用普通字体的唯一四级结构：

```markdown
#### 【长鑫科技(688825.SH)| 存储】
#### 【兆易创新(603986.SH)｜江波龙(301308.SZ)| 存储】
#### 【存储】
```

多个标的间用全角 `｜`；标的与主题间用半角 `|`，前无空格、后一个空格。无明确证券标的时只写主题。不得使用五级标题或虚构标的。

## 四、粗体与内嵌存疑

粗体仅有两种合法用途：

1. 独立行的 `**【……】**` 段落标题；
2. 正文中仍无法确认的最小必要片段，以及说明其不确定性的最短必要文字。

例如：

```markdown
公司提出**“十五五阶段达到100亿元产值”，但无法确认是期间内还是结束前**。
```

已确认的公司名修正、代码补充、转写修复和句子理顺使用普通字体。候选项只有一个但证据不足时仍按未解决存疑处理；候选唯一、上下文一致且证据充分时直接修正，并从 `doubtful_items` 和 verification sidecar 移除。

正文存疑不另复制为表格、脚注、括号外说明或整理者段落。内部 `doubtful_items`、verification sidecar 和 MAS artifact 继续记录候选、证据和处理理由；最终 Markdown 仅显示内嵌粗体内容。

股票代码不得加粗。为避免机械补全，专家交流和多人复盘会只在原文已有、需要区分同名实体，或作为多人复盘会已确认标题标的时写证券代码；公司交流的“会议标的”必须写已核验代码。
