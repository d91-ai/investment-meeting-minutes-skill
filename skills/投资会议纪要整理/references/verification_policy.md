# 名称、代码与术语核验

## 目标

只解决会议中名称、证券代码和术语的身份问题。外部资料不能补写或裁决会议陈述。

## 判断顺序

1. 不在孤立句子或单个分包内定案。先利用整场会议结构、同会话材料和用户纠正；对每个候选检查其在本场会议中的全部出现位置及相关上下文，不为此重新做一遍全文语义审查。
2. 利用附近解释、同义复述、数字关系、并列词、前后问答和同会重复出现，判断名称、代码、术语或听写片段是否已经能够唯一识别。
3. 当前会议仍不能解决时，区分“公开身份问题”和“私有会议事实”。对公司、机构、证券代码、产品、技术、型号和缩写等公开身份问题，在工具可用时必须先做一次定向本地或外部查询；可合并查询少量候选，但不扫描全文建立实体清单。
4. 查询结果与上下文共同指向唯一形式时自动修正并关闭候选；不得因为原始转写不同、曾被某个分包标记或缺少第二个证据源而继续保留存疑。
5. 只有查询后仍有两个以上合理解释、可靠证据相互冲突，或纯文本/音频确实无法恢复原句时，才保留原始表述并加入 `doubtful_items`。

## 每个候选的唯一结论

按以下顺序判断，并为每个候选赋予且仅赋予一个内部 verdict：

1. `preserve_as_meeting_uncertainty_no_doubt`：片段表达的是发言人的估计、听说、不知道、不便披露、需要查证或其他业务事实不确定性，而不是名称、代码、术语或听写身份不清。保留原有限定语，不进入 `doubtful_items`，也不做外部事实裁决。
2. `resolved_by_context`：检查该候选在当前会议中的全部出现位置、相关上下文和用户纠正后，只有一个解释能够同时解释原始词形、附近说明、数字或并列关系、前后问答及同会重复出现。采用该解释并关闭候选，不进入 `doubtful_items`。
3. `resolved_by_identity_evidence`：当前会议不能单独闭合，但允许的公开身份查询或可靠身份资料与会议上下文共同指向唯一名称、代码或术语。只修正身份形式，不改变会议中的关系、数字、观点或确定程度；关闭候选，不进入 `doubtful_items`。
4. `genuinely_doubtful`：完成上述检查，并对可查询的公开身份问题完成一次可用的定向查询后，仍有两个以上不能排除的合理解释、可靠证据存在实质冲突，或原句确实无法从文本/音频恢复。保留原始片段并进入 `doubtful_items`。

缺少联网、查询无结果、原始 ASR 形式不同、候选曾被分包标记、业务陈述没有公开证明，均不能单独支持 `genuinely_doubtful`。选择 `genuinely_doubtful` 时必须在内部说明仍不能排除的至少两个解释，或指出发生实质冲突的可靠证据；如果做不到，应回到前三类重新判断，不得用“为稳妥起见”生成存疑。

能够唯一识别且不存在实质冲突时自动处理，不加入 `doubtful_items`，也不请求人工确认。是否属于专业名词不能单独构成存疑理由。不得用永久术语白名单、正则放行表、硬编码词表或“专业名词一律存疑”替代模型判断。

像“A，刚才说错了，是 B”这样的同会话明确纠正，在 B 只对应一个合理身份时按 B 自动结案；不得因为 A 和 B 都出现在材料中就生成存疑行。用户对公司名、股票代码、术语、候选项或事实边界的明确纠正/确认属于高优先级人工修正；纠正已经唯一消歧时应关闭对应存疑。只有纠正仍与独立可靠证据冲突时，才记录冲突并保留为存疑。

本轮没有联网不能制造存疑项：如果当前会议证据已经唯一，缺少外部查询不是疑点。反过来，如果某个公开身份问题仅因尚未执行可用查询而不确定，应先查询，不能直接进入存疑。

## 允许外部确认的内容

- 公司、品牌或机构的正式名称；
- 证券代码与公司身份的对应关系；
- 行业、产品、技术、型号或缩写的公开含义。

查询时只发送候选名称、代码、术语和必要公开别名。不得发送原始会议长段、发言人身份、私有路径、未公开客户/订单关系、数字、预测或其他机密上下文。

## 不由外部资料裁决的内容

- 客户、供应商、竞争关系；
- 订单、产能、价格、财务数字和时间节点；
- 预测、内部进展、产品归属和发言人判断；
- 专家“不知道、估计、听说、不方便披露、需要查资料”等原始不确定表达。

这些都是应忠实保留的会议内容。不能因为无法从公开资料确认而删除、改写、降级或请求人工确认。

## 正文处理

- 外部核验结果不得作为批量替换或规范化发言正文的依据。
- 只有当前会话证据或可靠身份信息能证明明显 ASR 错听时，才修正文中的形式，并在最终来源复核中确认没有改变含义。
- 证券被模型判断为正文中的投资标的时，写成 `标准名称(已确认代码)`。
- 未确认 ticker 只能在正文中加粗保留候选名称和代码，不得进入标题或标的行。
- 客户、供应商、竞争对手、可比公司、上下游或背景公司不因是上市公司就自动补代码或进入标的标题。

## doubtful_items

只有真实存疑才建立内部记录：

```text
- 原始表述
- 存疑类型：公司或证券标的 / 行业术语 / 来源听写
- 当前判断
- 候选项
- 上下文依据
- 检索或证据路径
- 最终处理
```

最终 Markdown 的存疑表从该清单生成。基础流程不生成 verification sidecar，也不建立候选 manifest、原因码状态机、验证 shard 或 assembly receipt。

长材料分包只能提交少量待主流程判断的候选片段。最终 `doubtful_items` 由主流程检查候选在整场会议中的全部相关上下文并完成必要的定向查询后一次确定；不得合并各分包的局部存疑清单充当终稿。

每个长材料候选只在运行内存中携带原始片段、`package_id` 和 `turn_id`（或其他可靠源位置）以及该 occurrence 的最小前后文。主流程按这些位置回看同一候选在当前会议中的全部 occurrence，包括由模型判断的明显 ASR 变体和跨段最小相邻上下文，合并后只保留一个 verdict。该定点回看不是全文二次语义重写，也不生成 sidecar、manifest 或其他新产物。

## 生成时检查

direct 路径在同次生成中检查；长材料由各分段标记候选，主流程组装后只对候选逐项定点检查：

- 已修正的名称、代码和术语是否由当前会话或可靠身份信息唯一支持；
- 每个候选是否只有一个 verdict，且只有 `genuinely_doubtful` 被投影到最终存疑表；
- 是否把专业词类别本身误当成存疑理由；
- 是否存在“上下文已唯一”或“尚未执行可用公开查询”却仍被列入存疑的项目；
- 是否把发言人的业务不确定性误列成整理存疑；
- 是否由外部资料补写或改写了会议没有说过的关系、数字或观点；
- 多人复盘会的标的标题是否只包含当前段落明确看好的已确认证券标的。
