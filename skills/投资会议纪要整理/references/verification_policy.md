# 核验、存疑与标的归因规则

本文件定义证据边界、名称和代码核验、`doubtful_items`、AI 判断隔离及多人复盘会标的归因。外部资料只能确认名称、代码、术语和公开事实，不得补写会议没有表达的新结论。

## 一、证据层级

### 1. source evidence

原始音频、音频转写、用户文稿、人工初审稿和同会话补充说明构成会议内容的最高优先级证据。会议中的观点、数字、动作、条件和不确定性只能从这些材料中整理。

混合来源输入时，先比较覆盖完整度、发言顺序、逐字性、时间戳可靠性、ASR 噪声、遗漏和人工校正痕迹，再选择质量更高的一侧作为正文主源；另一侧只用于交叉核对。证据冲突且无法判断时进入 `doubtful_items`，不得静默覆盖。

用户在同一会话中对公司名、代码、术语或事实边界作出的明确确认属于高优先级人工修正；若其与源材料或可靠公开事实冲突，仍应记录冲突并保留存疑。

### 2. local reference evidence

本地证券代码表、公司别名表、术语表和候选查询脚本只用于生成候选、缩小检索范围，不能单独支持 `confirmed`。多候选、低置信或数据过期时继续核验或保留存疑。

### 3. external verification path

优先使用交易所、公司公告、公司官网、监管或协会资料；必要时使用可靠行业资料和财经信息。外部查询只发送候选实体、证券代码、术语和最小公开事实关键词，不发送私有会议长段、发言人身份、私有链接或未公开业务上下文。

外部证据与 source evidence 冲突时，不得用外部结论改写发言人的原始表达；应保留源材料的表达边界并进入存疑流程。

## 二、名称和证券代码核验

常用本地资源位于 `$INVESTMENT_MINUTES_WORKSPACE/03 Resources`，包括 A 股代码表、全球证券代码表和公司别名表。

核验顺序：

1. 可用的实时证券数据源；
2. 本地 A 股代码表；
3. 本地港股、美股及其他市场代码表；
4. 交易所、公告、公司官网或其他专业来源。

规则：

- 未确认的证券代码不得进入标题；
- 本地多候选匹配不能作为最终确认；
- 不局限于 A 股，港股、美股及其他上市证券出现时同样核验；
- A 股优先使用 `.SZ`、`.SH`、`.BJ`，港股使用 `.HK`，其他市场沿用可靠代码源；
- 候选名称或代码仍无法确认时，只能作为正文最小存疑片段和最终存疑表项目处理。

以下高风险信息写入终稿前必须核验：公司和证券代码、客户与供应商、订单与产能、价格与收入利润、估值与市值、时间节点、政策事件、产品型号、技术路线和专业术语。

买入、卖出、加减仓和重点跟踪等个人动作必须逐项回到当前源材料，核对动作主体、标的、方向、条件和原句措辞；外部资料不能证明或否定个人动作，只能核验动作中涉及的公开实体和事件。

## 三、AI 判断与正文边界

`## 一、发言整理` 只能出现源材料中的发言内容及必要的正常编辑。AI 的判断、解释、总结、推论、补充背景、核验路径、处理说明和候选项不得进入正文。

AI 核验信息只能进入以下位置：

- 内部 `doubtful_items`；
- verification sidecar；
- MAS 过程 artifact；
- 最终存疑表的“当前判断”“候选项”等审核列。

已确认的名称纠正、代码补充、错字修复、断句清理和句子理顺使用普通字体。只有源材料中仍无法确认的最小片段在原句原位置加粗，并由同一 `doubtful_items` 项派生最终存疑表。不得在正文另设整理者说明段落，也不得把候选解释、核验结论或时间戳插回正文。

## 四、doubtful_items

先建立唯一内部 `doubtful_items`，再从同一清单派生正文存疑标记、最终存疑表和 verification sidecar。sidecar 不得形成第二套独立判断。

每条记录包含：

- `原始表述`：源材料中的最小存疑片段；
- `存疑类型`：人名、说话人身份、公司或证券标的、行业术语、数字或时间、其他业务事实；
- `当前判断`：确认、保留原文、暂不采信或待人工确认；
- `候选项`：证券候选能匹配代码时写标准名称和代码；
- `是否需要 sidecar`：纯人名或纯身份为 `false`，其他业务疑点为 `true`；
- `上下文依据`：原文位置、发言人、小段主题及可用时间线索；
- `检索/证据路径`：本地候选和外部可靠来源；
- `最终处理`：普通字体写入正文、原句原位加粗并进入存疑表、或不写入正式标题。

不得只用“待确认”“需核实”“未查到”“听不清”代替当前判断和候选项。每条 sidecar 记录必须能回到终稿的一条非人名存疑行；正文、存疑表与 sidecar 冲突时，回到唯一 `doubtful_items` 修正后重新派生。

统一核验要求：

1. 先用会议上下文判断候选是否语义匹配；
2. 再用至少一种可靠外部证据核验，本地候选和 ASR 输出不能单独确认；
3. 外部资料只确认实体、代码、术语和公开事实，不补写观点；
4. 证据冲突、不足或不能唯一确认时，保留最小原文片段并进入存疑表；
5. 纯人名和身份疑点不得与公司、证券、术语、数字等业务疑点混淆。

## 五、时间戳规则

可靠存疑时间戳只能来自 sentence/phrase 级 anchor，或 `source=sensevoice_vad_segment` 且 `duration_ms <= 10000` 的短 VAD segment。其他粗粒度范围只作为内部复核线索。

可靠时间戳可以进入 verification sidecar、MAS artifact 和最终存疑表的时间戳列，但不得进入发言整理正文。没有可靠锚点时使用无时间戳存疑表，不写占位值。

## 六、正常校对边界

- 修正明显 ASR 错词，清理独立寒暄、无意义重复、噪声、纯口头填充和错误断句；寒暄与实质内容相连时只删除寒暄；
- 保留原始判断、条件、语气、数字、时间、交易动作、第一人称和不确定表达；
- 逐句核对否定、双重否定、自我纠正和转折方向；连续否定词不得通过全局替换、正则删词或固定保留一个字的方式机械处理；
- “不是 A，而是 B”“可能”“未必”“暂时”“倾向于”等方向或强度信息必须完整保留；
- 不得为追求顺滑而删除例子、原因链、限定条件、转折、比较对象或反复强调；
- 公司名、代码、英文缩写和行业术语结合上下文及可靠证据核验；
- 不因外部资料更完整而覆盖源材料中的不确定表达；
- 不用公开资料补写原文没有的客户名、订单额、业绩预测或投资结论；
- 传闻、未公开信息和无法确认的业务事实不得升级为确定事实。

## 七、多人复盘会标的归因

标的归因依赖语言模型结合上下文作语义判断，不依赖关键词、正则或固定动作映射。

核心规则：

- 最先提到或频次最高的公司不自动成为标题标的；
- 客户、供应商、竞争对手、可比公司、上下游实体、产业背景和偶然提及对象不得进入小段标题的标的部分；
- 外部资料不得把会议材料没有出现的公司补入标题；
- 正文中确属证券标的的实体，无论观点方向如何，均写为 `标准名称(已核验代码)`；背景实体不自动按证券标的处理；
- 只有当前小段明确正向、名称和代码已确认的证券标的进入标题的标的部分；看空、回避、减仓或谨慎对象只留在正文；
- 多个明确正向标的共享同一主题和逻辑链时，可以进入同一个四级小段标题，并保持原文出现顺序；逻辑不同则拆段；
- 没有符合条件的明确证券标的时只写主题标题，不得虚构标的；
- `ticker_status` 非 `confirmed` 的候选不得进入标题。

终稿前逐段进行模型语义审查：

1. 小段标题是否使用共享输出契约定义的唯一四级结构；
2. 标的部分是否只包含本段明确正向、已核验且属于核心内容的证券；
3. 是否混入负面、回避、减仓、顺带提及或背景关系实体；
4. 是否漏掉同一主题中明确正向的主要标的；
5. 是否出现源材料没有提到、仅由外部资料或整理者补充的公司；
6. 多标的是否确实共享主题和逻辑链，排列是否符合原文顺序；
7. 主题是否由本段源材料直接支持；
8. 正文证券名称和代码是否完整、准确且不改变原意。

发现问题时，主流程只修正 Markdown 的分段、四级小段标题和正文衔接；修正后重新完成适用审核，再进入结构校验。
